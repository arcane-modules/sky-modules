# Пакет `@sky-modules/core`

## Контекст
Нужен механизм traits и функция `compose` для сборки класса из нескольких traits с полной типизацией. Trait — обычный класс с фиксированным API, как математика Three.js (`Vector2`, `Color`). Состояние хранится только в экземпляре, методы — в прототипе.

## Цель
Дать TypeScript-способ собирать класс из нескольких trait-классов так, чтобы:
- методы лежали в `prototype` один раз (не на каждом экземпляре);
- каждое поле существовало в объекте в единственном экземпляре;
- `compose` принимал только классы, соблюдающие API trait, и проверял это на этапе компиляции;
- TypeScript выводил объединённый тип экземпляра и отклонял несовместимые поля и методы.

## Принципы
- **Zero dependencies** — только TypeScript и рантайм JS.
- **Конструктор выделяет, `set` присваивает** — конструктор создаёт вложенное состояние (массивы, вложенные векторы, колбэки) и вызывает `set`; `set` только присваивает.
- **Один объект** — у экземпляра композиции каждое поле в единственном экземпляре; вложенное состояние traits переносится в него при создании.
- **Ручная сборка `set`** — `set` композиции пишет пользователь и сам вызывает `Trait.prototype.set.call(this, …)` (без накладных расходов).
- **Дедупликация** — один и тот же trait, переданный несколько раз, учитывается однократно (сравнение по ссылке).
- **Явные ошибки** — конфликты ловятся в типах и в рантайме.

## Состав пакета

### 1. Trait

Trait — класс с API:

```typescript
class Vector2 {
    x!: number
    y!: number

    constructor(x = 0, y = 0) {
        this.set(x, y)
    }

    set(x: number, y: number): this {
        this.x = x
        this.y = y
        return this
    }

    copy(other: Vector2): this {
        this.x = other.x
        this.y = other.y
        return this
    }

    clone(): this {
        return new (this.constructor as new () => this)().copy(this)
    }

    length(): number {
        return Math.hypot(this.x, this.y)
    }
}
```

Требования (проверяются в типах `CheckTrait`):
- класс создаётся без аргументов: значения по умолчанию (`constructor(x = 0, y = 0)`, как в Three.js) или пустая перегрузка `constructor()`;
- класс создаётся с аргументами `set`. Если `set` принимает объединение кортежей (`[color] | [r, g, b]`), конструктор должен принимать каждый кортеж;
- `copy(other): this` и `clone(): this`.

Соглашение (не проверяется типами): `copy` трейта присваивает поля напрямую, а не через `this.set` — внутри композиции `this.set` принадлежит композиции.

Тип `Trait<A, I>` описывает такой класс: `new (): I`, `new (...args: A): I`.

### 2. `compose`

```typescript
import { compose } from '@sky-modules/core'

class Rect extends compose(Vector2, Size) {
    constructor(x = 0, y = 0, width = 0, height = 0) {
        super()
        this.set(x, y, width, height)
    }

    set(x: number, y: number, width: number, height: number): this {
        Vector2.prototype.set.call(this, x, y)
        Size.prototype.set.call(this, width, height)
        return this
    }
}
```

- Базовый класс конструируется без аргументов и для каждого trait выполняет `Object.assign(this, new Trait())` — так появляется вложенное состояние (`Matrix4.elements`, `Box3.min`/`max`, `_onChangeCallback`). Цена — временный объект на trait при каждом создании. Поля `#private` таким способом не переносятся.
- Конструктор и `set` композиции задаёт пользователь. `abstract` не используется; принуждение — через проверку `Trait` у места использования (например, при передаче композиции в другой `compose`).
- `compose` генерирует:
  - `copy(other): this` — вызывает `copy` каждого trait в порядке списка;
  - `clone(): this` — `new this.constructor().copy(this)`.
- Методы traits (кроме `constructor`, `set`, `copy`, `clone`) собираются по цепочке прототипов каждого trait (до `Object.prototype`) и кладутся в прототип базового класса один раз.
- Один и тот же trait в списке учитывается один раз.

### 3. Правила конфликтов

| Ситуация | Типы | Рантайм |
|---|---|---|
| Класс не соблюдает API trait | ошибка компиляции на `compose` | — |
| Одно поле у двух traits с одинаковым типом | допустимо | — |
| Одно поле у двух traits с разными типами | ошибка компиляции на `compose` | — |
| Один и тот же член прототипа у двух traits с разными реализациями | ошибка компиляции при разных типах | `Error` в `compose` |
| Одна и та же реализация у двух traits (общий предок) | допустимо | учитывается однократно |
| Один и тот же trait передан дважды | допустимо | учитывается однократно |

### 4. Типы результата

- Тип экземпляра = объединение экземпляров traits без `set`, `copy`, `clone` (`MergeShapes`) плюс `copy(other: this): this` и `clone(): this`.
- Тип конструктора — `new () => экземпляр`.

## Ограничения
- Тип `this` в методах trait после объединения фиксируется на классе trait (например, `add(): Vector2`), а не на композиции.
- Наличие собственного конструктора у композиции типами и рантаймом не проверяется.
- Зависимости между traits не поддерживаются: trait перечисляется в `compose` явно.

## Критерии готовности
- `tsc --noEmit` и `vitest run` в `packages/core` проходят без ошибок.
- Тесты покрывают: `set`/`copy`/`clone` композиции, выделение вложенного состояния, значения по умолчанию и перегрузки конструктора, объединение кортежей в `set`, методы в прототипе в единственном экземпляре, методы унаследованных traits, дедупликацию, рантайм-конфликты, типовые проверки API trait и конфликтов полей (`@ts-expect-error`), выведенный тип экземпляра (`expectTypeOf`), использование композиции как trait.
