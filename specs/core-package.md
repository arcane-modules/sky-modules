# Пакет `@sky-modules/core`

## Контекст
Пакет `packages/core` пуст. Нужен механизм traits (stateless-поведение и инициализация) и функция `compose` для сборки классов из нескольких traits с полной типизацией. Состояние хранится только в экземпляре класса, traits его не владеют.

## Цель
Дать TypeScript-способ собирать класс из нескольких traits так, чтобы:
- методы лежали в `prototype` один раз (не на каждом экземпляре);
- каждое поле существовало в объекте в единственном экземпляре;
- конструкторы traits вызывались через `init` с тем же `this`;
- TypeScript выводил объединённые типы полей и методов и отклонял несовместимые поля и методы на этапе компиляции.

## Принципы
- **Zero dependencies** — только TypeScript и рантайм JS.
- **Stateless traits** — trait не хранит данные, только описание полей (на уровне типов), методов и `init`.
- **Один объект** — `compose` не копирует поля между объектами.
- **Дедупликация** — один и тот же trait, переданный несколько раз, учитывается однократно (сравнение по ссылке).
- **Явные ошибки** — конфликты ловятся в типах и в рантайме.

## Состав пакета

### 1. `defineTrait`

```typescript
import { defineTrait } from '@sky-modules/core'

interface PositionFields { x: number; y: number }

const Position = defineTrait<'Position', PositionFields, {}, [x: number, y: number]>({
  name: 'Position',
  init(x, y) {
    this.x = x
    this.y = y
  },
})

const Point = defineTrait<'Point', PositionFields, { move(dx: number, dy: number): void }, []>({
  name: 'Point',
  move(dx, dy) {
    this.x += dx
    this.y += dy
  },
})
```

Параметры generic:
- `N extends string` — уникальное имя trait (ключ аргументов конструктора);
- `F extends object` — поля, которые trait ожидает/задаёт;
- `M extends object` — методы;
- `A extends unknown[]` — аргументы `init` (по умолчанию `[]`).

Внутри методов и `init` `this` имеет тип `F & M`.

### 2. `compose`

```typescript
import { compose } from '@sky-modules/core'

class Shape extends compose(Position, Point, Rect) {}

const s = new Shape({ Position: [10, 20], Rect: [100, 50] })
s.move(5, 10)     // x = 15, y = 30
s.area()          // 5000
```

- Аргументы конструктора — объект, ключ — `name` trait, значение — кортеж аргументов его `init`.
- Обязательность: если у trait `init` с параметрами — ключ обязателен; если аргументов нет — ключ опционален.
- Порядок вызова `init` — порядок в списке аргументов `compose`.
- Один и тот же trait в списке учитывается один раз.

### 3. Правила конфликтов

| Ситуация | Типы | Рантайм |
|---|---|---|
| Одно поле у двух traits с одинаковым типом | допустимо | — |
| Одно поле у двух traits с разными типами (`x: number` и `x: string`) | ошибка компиляции на `compose` | — |
| Один и тот же метод у двух traits с разными функциями | ошибка компиляции | `Error` в `compose` |
| Один и тот же trait передан дважды | допустимо | учитывается однократно |
| Два разных trait с одним `name` | — | `Error` в `compose` |

### 4. Типы результата

- Тип экземпляра = `Fields(T1, T2, …) & Methods(T1, T2, …)`.
- Поля объединяются через `MergeShapes`, несовместимые поля помечаются маркером `{ __conflict: K }`.
- Тип аргументов конструктора строится из `name` и `A` каждого trait.

## Ограничения (первая версия)
- Зависимости между traits (`requires`) не поддерживаются: trait должен быть перечислен в `compose` явно.
- Поля не проверяются в рантайме: если `init` не задал поле, тип объекта всё равно его содержит. Ответственность — на авторе trait.
- Генерики `defineTrait` указываются явно: TypeScript не умеет частично выводить параметры.

## Критерии готовности
- Команды `tsc --noEmit` и `vitest run` в `packages/core` проходят без ошибок.
- Тесты покрывают: stateless-поведение, `init` с аргументами, дедупликацию, рантайм-конфликты методов и имён, типовые конфликты полей (через `@ts-expect-error`) и выведенные типы конструктора и экземпляра (через `expectTypeOf`).
- Методы находятся в `prototype` базового класса, собранного `compose`, в единственном экземпляре; у экземпляра собственных методов нет.
